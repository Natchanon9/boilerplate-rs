| # | Severity | Rule | Location | Finding | Failure scenario | Suggested fix |
|---|----------|------|----------|---------|----------|---------------|
| 1 | major | SEC-9 | [main.rs:14](../../../crates/bootstrap/src/main.rs#L14), [xtask main.rs:40](../../../xtask/src/main.rs#L40) | Same defect as feature 2, finding 1: a malformed `.env` line is printed with `{err}`, and dotenvy's `LineParse` error includes the line text, which can be a secret. | `AUTH_JWT_SECRET="abc` (unterminated quote) makes `app` and `cargo xtask token` print the secret to stderr. | Print only the line index; add a test. |
| 2 | minor | SEC-8 | [Makefile:12](../../../Makefile#L12), [Makefile:72](../../../Makefile#L72) | The `format!` check is a one-line, uppercase-keyword regex over `format\|write\|writeln\|concat`. I ran it: `format!("select ... {}")`, a `format!(` whose string is on the next line, `+ &x`, and `[..].concat()` all pass. AGENTS.md says SQL in `format!` fails `make sql-check`. The real backstop is sqlx 0.9 (a non-`'static` string needs `AssertSqlSafe`/`leak`, which the other grep blocks), so the risk is limited. | A lowercase `format!("select ... {id}")` handed to `AssertSqlSafe` is blocked by the first grep; the second grep alone would miss it. | Make the pattern case-insensitive (`(?i)`) and multi-line (`grep -Pzo`), or word the docs as "AssertSqlSafe, QueryBuilder, and leak are blocked; sqlx rejects the rest". |
| 3 | minor | TEST-1 (SEC-1, xtask token) | [token.rs:153](../../../xtask/src/token.rs#L153) | The "token the app accepts" claim is not tested end to end. xtask cannot depend on `http-api`, so its test rebuilds the validation rules by hand; `security.rs` signs its own tokens. If the verifier gains a required claim, the xtask test still passes. | The app starts requiring `nbf` or `typ`; `cargo xtask token` output is rejected with 401 and `make verify` is green. | In `crates/bootstrap/tests/security.rs`, run the `xtask` binary (`cargo xtask token`, with a fixed env) and send its output to the wired router. |
| 4 | nit | SEC-1 | [auth.rs:86](../../../crates/http-api/src/auth.rs#L86) | `sub` is required but may be empty (`"sub": ""` passes). | An owned resource (SEC-3) filters by `sub`; every empty-`sub` token shares one owner. | Reject an empty `sub` in `verify`. |

AC coverage: SEC-1 has unit tests for missing/non-Bearer/empty/garbage/bad-signature/expired/future-`nbf`/`alg: none`/other algorithms/wrong `iss` and `aud`/missing `sub` and `exp` ([auth.rs](../../../crates/http-api/src/auth.rs) tests) and wired tests in `security.rs`. Reading `Validation` in `JwtVerifier::hs256` confirms HS256 is pinned, the required claims are `sub`, `exp`, `iss`, `aud`, and `nbf` is checked when present. SEC-2: `RequireScope` is fail-closed without a `Principal`, with 403 tests (`security.rs`, `track_http.rs` `ac_7_*`). SEC-4: `UnknownFields` tested (`input.rs`, `ac_2_*`). SEC-5: page size cap tested; the body limit is axum's implicit 2 MiB default, tested only on a stand-in router (see feature 3, finding 1); rate limit and timeout are deferred. SEC-6: `CACHE_DEBUG_HEADER` with `APP_ENV=production` is refused (`config.rs` unit tests and `cache_debug_header_stops_startup_in_production` in `cli.rs`, in any letter case); error bodies carry no cause (`error.rs` test). SEC-9: secrets are `SecretString`, `hide_env_values` is set on the three secret args, `info env` redacts the password and `*password*` query parameters (`runtime_ac_3_*`), and short-secret errors do not echo the value (`stack_ac_5_*`); there is no test that a token or `Authorization` header never reaches the logs (the code logs only a fixed reason, and `TraceLayer` does not record headers). SEC-10: `cargo deny --offline check bans`, `licenses`, `sources`, and `advisories` all pass. SEC-11: `unsafe_code = "forbid"` and the three clippy lints are in `[workspace.lints]`, every crate and xtask opts in, and `cargo clippy --workspace --all-targets --all-features -- -D warnings` passes. SEC-13: logs use structured fields and no claim values.

Verdict: changes requested (finding 1; the rest are minor or nit).

## Outcome (2026-10-12, engineer decision)

- Fixed: the `.env` parse-error leak (SEC-9), in commit `fix: keep dotenv parse errors from printing secrets`.
- Fixed in part: the SQL check (SEC-8), in commit `build: catch lowercase SQL statements in sql-check`. It now also catches `select .. from`, `insert into`, `update .. set`, and `delete from` in any case. A SQL string that starts on a later line than the macro, and `+` or `.concat()` joins, are still not caught.
- Accepted as known trade-offs, not fixed in the MVP: the other findings in this report.
